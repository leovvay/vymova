# Vymova Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Локальное веб-приложение в Docker. Репетитор загружает запись урока, отмечает голоса и получает один общий PDF с разбором ошибок произношения, грамматики и лексики каждого студента — с тем же качеством, что у прототипа.

**Architecture:** Бэкенд на FastAPI раздаёт API и собранный фронтенд. Конвейер — цепочка идемпотентных шагов. Каждый шаг пишет свой артефакт в папку урока на смонтированном томе `/data`. Один фоновый воркер выполняет шаги, а после перезапуска продолжает с первого шага без артефакта. Внешние слои — ElevenLabs Scribe и Gemini. Акустика — локальный wav2vec2 на CPU. PDF печатает Chromium из HTML-шаблона.

**Tech Stack:**
- бэкенд: Python 3.12, FastAPI, uvicorn, httpx, Jinja2;
- акустика и голоса: torch CPU, transformers, speechbrain (ECAPA);
- медиа и PDF: ffmpeg, Chromium (Debian);
- фронтенд: React + Vite + TypeScript;
- упаковка: Docker (linux/amd64), GitHub Actions → GHCR.

**Spec:** `docs/superpowers/specs/2026-10-26-vymova-design.md`. Читать вместе с прототипом `docs/prototype/`.

## Global Constraints

- **Тест-файлов в репозитории нет** (правило Влада: тесты — только если попросит). Каждая проверка — команда плюс ожидаемый вывод. Одноразовые скрипты проверки лежат вне репозитория, в `/tmp/vymova-scratch/`, и удаляются после задачи.
- **Код по предметным областям:** одна feature-папка на область, типы в отдельном `model.py`, `__init__.py` — фасад области. Во фронтенде `features/<area>/` и `index.ts` на каждую. Файл больше ~1500 строк обязательно разбивается.
- **UI** проектируется и собирается через навык `/impeccable` (Opus).
- **Тексты:** весь UI и отчёт по-русски. Репетитор в промптах никогда не называется носителем языка.
- **Сеть:** порт `127.0.0.1:8765`. Данные лежат на томе `/data`, на хосте это `%USERPROFILE%\Documents\Vymova\`. Хостовый путь контейнер получает через `HOST_DATA_DIR`.
- **Ключи:** только в `/data/settings.json`. Никогда не логируются, не попадают в образ и в репозиторий.
- **Публичный репозиторий:** записи уроков, имена реальных студентов, ключи и артефакты уроков в git не попадают (`.gitignore` уже их исключает).
- **Коммиты** только от `leovvay <41321050+leovvay@users.noreply.github.com>` (уже настроено в репозитории). `gh` переключать на `leovvay` перед операциями с GitHub и возвращать на `kma-leovvay` после.
- **Scribe:** без `language_code`, `diarize=true`, `timestamps_granularity=word`, `tag_audio_events=true`. Слова длиннее 3 с обрезаются: `start = end - 0.6`.
- **Клипы:** соседние слова одного спикера склеиваются при паузе < 1.5 с, отступы −0.3 / +0.4 с, реплики только из филлеров пропускаются (список `FILL` из `docs/prototype/clips.py`).
- **Слепая проверка:** две разные модели, «подтверждено» — только при валидных цитатах из обеих записей. Если двух разных моделей нет, «подтверждено» не формируется, а отчёт предупреждает.
- **Акустика:** эталон — словарное IPA (LLM + Викисловарь) с калибровкой по носителям. espeak-ng и речь репетитора эталоном не используются. Модели грузятся по одной, слои `Linear` квантуются в int8. Акустику можно отключить.
- **Нагрузка:** до 4 студентов на урок. Один первый проход Gemini на урок, слепая проверка — отдельно на каждого студента.
- **Отчёт:** один PDF на урок, без страницы методики.

## Review Focus

1. **Кириллица и пробелы в пути пользователя Windows** (`C:\Users\Владислав\…`). Монтирование тома, ссылки на клипы в PDF и сообщения `.bat` должны работать. → проверка в Task 10 (ссылки) и Task 12 (`.bat`, монтирование).
2. **Диаризация разбила одного человека на два голоса или склеила двоих.** Одно имя на два голоса — это один студент. «Пропустить» — голос не анализируется. → Task 3.
3. **Сбой API:** неверный или просроченный ключ, 429, невалидный JSON, `finishReason` не `STOP`. До 3 повторов с паузой, потом шаг `failed` с русским сообщением и кнопка «Повторить», которая продолжает с этого шага. → Task 2 (раннер) и Task 5 (клиент Gemini).
4. **Перезапуск контейнера или сон ПК посреди обработки** — обработка продолжается с первого незавершённого шага, готовые шаги не повторяются и не оплачиваются второй раз. → Task 2.
5. **У студента мало речи (< 30 с) или почти вся речь на другом языке** — его раздел говорит «мало речи для разбора» и показывает, что есть, без пустых таблиц и без падения. → Task 9 и Task 10.

- результат и состояние: `report.html`, `report.pdf`, `state.json`.

    - загрузка из `MODELS_DIR`, `torch.quantization.quantize_dynamic(Linear, qint8)`, CPU;
    - словарь токенов читается из `vocab.json` — без phonemizer;
    - фоны раскладываются по словам по центру CTC-кадра в `[start−0.04, end+0.04]`;
    - модель после использования выгружается (`del`, `gc.collect()`).
  - `lexicon.expected_ipa(words: list[str], gemini_key) -> dict[str, str]`:
    - эталонное IPA с ударением, по одному слову;
    - кэш `/data/lexicon_cache.json`;
    - Gemini пачками по 200 слов;
    - сверка с en.wiktionary (`/api/rest_v1/page/html/<word>`, `span.IPA` в разделе Ukrainian): при расхождении берётся Викисловарь и пишется в `lexicon_conflicts.log`.
  - `align.align(expected: list[str], heard: list[str]) -> list[tuple[str|None, str|None]]`:
    - Needleman–Wunsch: совпадение 0, замена внутри одного класса (гласные / звонкие-глухие пары / мягкий-твёрдый вариант) 1, прочая замена 2, вставка или удаление 1.5;
    - перед выравниванием снять `ˈ ˌ ː`, диакритики длины и тоны (цифры).
  - `align.ipa_tokens(ipa: str) -> list[str]` — токенизация IPA в набор символов модели (из её `vocab.json`).
  - `calibration.json`: `{model_id: {"expected→heard": rate}}` — доля замен на эталонный фон у носителей, только пары с n ≥ 20.
  - `build_calibration.py`:
    - FLEURS `uk_ua`, test-сплит, первые 400 высказываний (parquet с HF, CC-BY-4.0);
    - эталон через `lexicon.expected_ipa`, распознавание обеими моделями, выравнивание по высказыванию, подсчёт `expected→heard`.
    - В README — атрибуция FLEURS. (В спецификации был Common Voice; он закрыт регистрацией, FLEURS заменяет его с той же целью.)
