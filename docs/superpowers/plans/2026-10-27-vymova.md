# Vymova Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web application in Docker. The tutor uploads a lesson recording, marks the voices, and gets one combined PDF with an analysis of each student's pronunciation, grammar and vocabulary mistakes — at the same quality as the prototype.

**Architecture:** A FastAPI backend serves the API and the built frontend. The pipeline is a chain of idempotent steps. Each step writes its artifact to the lesson folder on the mounted `/data` volume. A single background worker executes the steps and, after a restart, continues from the first step without an artifact. The external layers are ElevenLabs Scribe and Gemini. Acoustics is a local wav2vec2 on CPU. The PDF is printed by Chromium from an HTML template.

**Tech Stack:**
- backend: Python 3.12, FastAPI, uvicorn, httpx, Jinja2;
- acoustics and voices: torch CPU, transformers, speechbrain (ECAPA);
- media and PDF: ffmpeg, Chromium (Debian);
- frontend: React + Vite + TypeScript;
- packaging: Docker (linux/amd64), GitHub Actions → GHCR.

**Spec:** `docs/superpowers/specs/2026-10-26-vymova-design.md`. Read it together with the prototype `docs/prototype/`.

## Global Constraints

- **No test files in the repository** (Vlad's rule: tests only if he asks). Every check is a command plus the expected output. Throwaway check scripts live outside the repository, in `/tmp/vymova-scratch/`, and are deleted after the task.
- **Code by domain:** one feature folder per domain, types in a separate `model.py`, `__init__.py` is the domain facade. In the frontend, `features/<area>/` with an `index.ts` for each. A file over ~1500 lines must be split.
- **UI** is designed and built via the `/impeccable` skill (Opus).
- **Texts:** the whole UI and the report are in Russian. In prompts the tutor is never called a native speaker.
- **Network:** port `127.0.0.1:8765`. Data lives on the `/data` volume, which on the host is `%USERPROFILE%\Documents\Vymova\`. The container gets the host path through `HOST_DATA_DIR`.
- **Keys:** only in `/data/settings.json`. Never logged, never included in the image or the repository.
- **Public repository:** lesson recordings, real student names, keys and lesson artifacts do not go into git (`.gitignore` already excludes them).
- **Commits** only from `leovvay <41321050+leovvay@users.noreply.github.com>` (already configured in the repository). Switch `gh` to `leovvay` before GitHub operations and back to `kma-leovvay` afterwards.
- **Scribe:** without `language_code`, `diarize=true`, `timestamps_granularity=word`, `tag_audio_events=true`. Words longer than 3 s are trimmed: `start = end - 0.6`.
- **Clips:** adjacent words of one speaker are merged when the pause is < 1.5 s, padding −0.3 / +0.4 s, utterances consisting only of fillers are skipped (the `FILL` list from `docs/prototype/clips.py`).
- **Blind check:** two different models, «подтверждено» (confirmed) only with valid quotes from both transcriptions. If there are not two different models, «подтверждено» is not produced and the report warns about it.
- **Acoustics:** the reference is dictionary IPA (LLM + Wiktionary) with calibration on native speakers. espeak-ng and the tutor's speech are not used as the reference. Models are loaded one at a time, `Linear` layers are quantized to int8. Acoustics can be turned off.
- **Load:** up to 4 students per lesson. One Gemini first pass per lesson, the blind check separately for each student.
- **Report:** one PDF per lesson, no methodology page.

## Review Focus

1. **Cyrillic and spaces in the Windows user path** (`C:\Users\Владислав\…`). Volume mounting, clip links in the PDF and `.bat` messages must work. → checked in Task 10 (links) and Task 12 (`.bat`, mounting).
2. **Diarization split one person into two voices or merged two.** One name on two voices is one student. «Пропустить» (Skip) — the voice is not analyzed. → Task 3.
3. **API failure:** an invalid or expired key, 429, invalid JSON, `finishReason` not `STOP`. Up to 3 retries with a pause, then the step becomes `failed` with a Russian message and a «Повторить» (Retry) button that continues from that step. → Task 2 (runner) and Task 5 (Gemini client).
4. **Container restart or PC sleep in the middle of processing** — processing continues from the first unfinished step, finished steps are not repeated and not paid for a second time. → Task 2.
5. **A student with little speech (< 30 s) or almost all speech in another language** — their section says «мало речи для разбора» (too little speech to analyze) and shows what there is, without empty tables and without crashing. → Task 9 and Task 10.

### Task 7: Acoustic recognizer, reference lexicon, alignment and calibration

**Files:**
- Create: `backend/vymova/analysis/acoustic/{recognizer,lexicon,align,__init__}.py`, `tools/calibration/build_calibration.py`, `backend/vymova/analysis/acoustic/calibration.json` (generated)

**Interfaces:**
- Produces:
  - `recognizer.MODELS = ["facebook/wav2vec2-lv-60-espeak-cv-ft", "facebook/wav2vec2-xlsr-53-espeak-cv-ft"]`.
  - `recognizer.phones_per_word(model_id, wav16k, turns, words) -> dict[int, list[str]]`:
    - loaded from `MODELS_DIR`, `torch.quantization.quantize_dynamic(Linear, qint8)`, CPU;
    - the token vocabulary is read from `vocab.json` — no phonemizer;
    - phones are assigned to words by the center of the CTC frame within `[start−0.04, end+0.04]`;
    - the model is unloaded after use (`del`, `gc.collect()`).
  - `lexicon.expected_ipa(words: list[str], gemini_key) -> dict[str, str]`:
    - reference IPA with stress, one word at a time;
    - cache `/data/lexicon_cache.json`;
    - Gemini in batches of 200 words;
    - cross-checked against en.wiktionary (`/api/rest_v1/page/html/<word>`, `span.IPA` in the Ukrainian section): on a mismatch Wiktionary wins and the case is written to `lexicon_conflicts.log`.
  - `align.align(expected: list[str], heard: list[str]) -> list[tuple[str|None, str|None]]`:
    - Needleman–Wunsch: match 0, substitution within one class (vowels / voiced-voiceless pairs / soft-hard variant) 1, any other substitution 2, insertion or deletion 1.5;
    - before alignment, strip `ˈ ˌ ː`, length diacritics and tones (digits).
  - `align.ipa_tokens(ipa: str) -> list[str]` — tokenization of IPA into the model's symbol set (from its `vocab.json`).
  - `calibration.json`: `{model_id: {"expected→heard": rate}}` — the rate at which native speakers' reference phone is substituted, only pairs with n ≥ 20.
  - `build_calibration.py`:
    - FLEURS `uk_ua`, test split, the first 400 utterances (parquet from HF, CC-BY-4.0);
    - the reference via `lexicon.expected_ipa`, recognition by both models, per-utterance alignment, counting `expected→heard`.
    - FLEURS attribution goes in the README. (The spec had Common Voice; it is gated behind registration, so FLEURS replaces it for the same purpose.)

### Task 8: Acoustic findings and the «подтверждено» adjudicator

**Files:**
- Create: `backend/vymova/analysis/acoustic/{findings,run}.py`, `backend/vymova/analysis/adjudication/{prompt.txt,validate,run,__init__}.py`

**Interfaces:**
- Consumes: Tasks 5–7.
- Produces:
  - `acoustic/<student>.json`: `[{pattern_key: "o→a", label_ru, model_id, k, n, native_rate, verdict: "confirmed"|"likely"|"unresolved", examples: [{clip, word, heard, expected}]}]`.
  - Verdict rules per `expected→heard` pattern with n ≥ 3:
    - `k/n − native_rate ≥ 0.4` for both models → `confirmed`;

    - the quote is a substring of the corresponding model's `phonetic` after NFC, lowercasing and whitespace collapsing;
    - with no valid quote from at least one transcription — downgrade to `possible` (if one is valid) or `rejected` (if none is).
  - `taught_in_lesson = true` if the clip's `teacher_reply` contains the finding's word.
